## maven_resolver 执行 mvn.cmd 未引入 central_url 修复
- 问题：`MvnTreeResolver.resolve()` 执行 `mvn dependency:tree` 时未传入配置中的 `maven.central_url`，导致走 Maven 内置默认 `repo.maven.apache.org`（与 `maven.central_url` 默认值 repo1.maven.org 等价），私有 Nexus 等自定义地址不生效。
- `dependency:tree` 无"远程仓库 URL"命令行参数，正确做法是用临时 settings.xml 的 `<mirror>`（`mirrorOf=*`）把全部远程仓库重定向到 central_url，再以 `-s <settings.xml>` 传入。
- 修复：`MvnTreeResolver` 在 `__init__` 读取 `maven.central_url`；新增 `_use_custom_central()`（非默认才注入）、`_build_settings_xml()`（生成临时 mirror settings）；`resolve()` 在自定义 central_url 时拼 `[mvn, "-s", settings, "dependency:tree", ...]` 并在 finally 删除临时文件；默认/空 central_url 不注入（行为不变）。新增 `tests/test_maven_resolver.py` 的 `TestMvnTreeCentralUrl`（自定义注入含 mirror、默认/空不注入）。全量 **41 单测通过**。已重建 `DTrack_offline.zip`（60 项）。
- 注意：`<mirrorOf>*</mirrorOf>` 也会重定向插件仓库解析；若 central_url 是只代理组件、不含插件的私有仓，maven-dependency-plugin 自身下载可能失败。一般私有 Nexus/Artifactory 是完整代理，无碍。

## maven_resolver 注入 settings 缺少 server 认证
- 问题：上一条注入的临时 settings.xml 只有 `<mirror>`，若 `central_url` 指向需认证的私有 Nexus/Artifactory，下载会 401/403（用户反馈"没有配置 maven servers 的用户名和密码"）。
- 修复：`config.py` 的 `maven` 段新增 `central_username`、`central_password`（默认 None）；`MvnTreeResolver.__init__` 读取；`_build_settings_xml()` 在 `central_username` 非空时追加 `<servers><server><id>dtrack-central</id><username>..</username><password>..</password></server></servers>`（id 与 mirror 的 id 一致，Maven 据此匹配认证）。更新 `dtrack.toml`/`dtrack.example.toml` 的 maven 段。新增 2 个用例（含凭据注入 servers / 无用户名则不注入）。全量 **43 单测通过**。已重建 `DTrack_offline.zip`（60 项）。

## Java 解析补全 <dependencyManagement>
- 问题：`java_analyzer.py` 只汇总 `<dependencies>`（`pom.direct_deps`），`<dependencyManagement>` 中声明的真实组件从未进入扫描，用户反馈"只解析了 dependencies，没解析 dependencyManagement"。
- 修复：新增 `_is_bom_import()`（type=pom + scope=import 视为 BOM 导入，跳过，非真实组件）与 `_collect_declared()`（汇总 direct + 受管，排除 BOM import，产出 `seed_deps`/`source_map`/`managed_decl`/`direct_keys`/`managed_keys`）。`analyze()` 把 `seed_deps` 作为 MavenCentralResolver 传递展开种子；`mvn dependency:tree` 路径遗漏的受管组件在解析后回补为 DIRECT 组件（tree_path="(dependencyManagement)"）；分类 `is_direct` 同时认可 managed_keys。受管组件同样服从全局 `analyze.exclude_scopes`（默认含 test）与 `exclude_test_frameworks`（默认 True）剔除规则——与 `<dependencies>` 行为一致。
- 新增 `tests/test_java_analyzer.py`（4 用例：受管 junit 纳入、BOM import 排除、回补逻辑）。全量 **47 单测通过**。已重建 `DTrack_offline.zip`（61 项）。
