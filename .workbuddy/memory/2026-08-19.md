## cmake_parser 命令名与左括号空格兼容
- 问题：`dtrack/analyzers/cc/cmake_parser.py` 的 `parse_cmake_text()` 用 `low.startswith("project(")` / `find_package(` / `add_library(` / `target_link_libraries(` 严格匹配命令；但 CMake 允许命令名与 `(` 间有空格（如 `project (Foo)`），此时 `startswith("project(")` 因中间空格而失败，导致依赖被漏解析。
- 修复：四处判断改为 `re.match(r"^project\s*\(", low)` 形式（允许 `\s*`）。`_args_of()` 内部正则本就带 `\s*\(`，参数提取不受影响。
- 新增 `tests/test_cmake_parser.py::test_command_name_space_before_paren`（空格写法全部识别：project/find_package/add_library/target_link_libraries）。全量 **51 单测通过**（原 50）。已重建 `DTrack_offline.zip`（61 项）。

## cmake_parser 命令名大小写不敏感
- 用户补充：CMake 命令名不区分大小写（`project`/`PROJECT`/`Project` 等价）。上一处仅处理了空格，未处理大小写。
- 修复：`parse_cmake_text()` 四处 `re.match` 增加 `re.I`（忽略大小写）；`_args_of()` 的 `re.search` 也加 `re.I | re.S`（原来只有 `re.S`）。`low = line.strip()` 本就不是小写化，配合 `re.I` 即可匹配任意大小写。
- 新增 2 用例：`test_command_case_insensitive`（全大写）、`test_command_mixed_case_and_space`（首字母大写+空格）。全量 **53 单测通过**（原 51）。已重建 `DTrack_offline.zip`（61 项）。

## cmake_parser 多行/续行/嵌套括号导致 _args_of 返回 None
- 问题（用户截图 `ADD_LIBRARY ( wcsp STATIC ${...} \ ... )`）：当命令跨多行用 `\` 续行，或含生成表达式 `$<...>` 嵌套括号时，旧实现有两类隐患：
  1. `_strip_comments()` 仅按括号深度合并，遇到 `\` 续行（括号已平衡却仍续行）可能被提前 flush，使单行缺 `)` → `_args_of` 旧正则 `\((.*?)\)` 找不到 `)` 返回 None → 命令被整条漏解析，库名/依赖名丢失（表现为 version=None 或依赖被当作外部）。
  2. `_args_of` 用非贪婪 `.*?\)` 在生成表达式内部的 `)` 处就截断，丢失后续真实依赖。
- 修复：`_strip_comments()` 识别行尾 `\` 续行（去掉续行符后继续累积，不立即 flush）；`_args_of()` 改为按**括号深度**匹配命令名左括号配对的右括号，未找到配对 `)` 时退化为取左括号后全部内容（至少拿到第一个参数，不再返回 None）。
- 新增 3 用例：反斜杠续行 ADD_LIBRARY（wcsp 入 local_libs）、生成表达式嵌套括号不截断、未闭合括号兜底返回库名。全量 **56 单测通过**（原 53）。已重建 `DTrack_offline.zip`（61 项）。

## maven_resolver 聚合父 POM 缺失子模块导致解析失败
- 问题（用户截图）：目标 POM 为 `packaging=pom` 的聚合父工程，`<modules>` 引用了本地不存在的子模块（如 `wmp-parent`），`mvn dependency:tree` 默认会构建整个 reactor，因读取不到子模块而报错退出，DTrack 的 Maven 解析流程失败。
- 修复：`dtrack/analyzers/java/maven_resolver.py` 的 `MvnTreeResolver.resolve()` 在运行前读取根 `pom.xml`：
  - 若检测到聚合父 POM 且任一 `<module>` 目录下缺少 `pom.xml`，直接给 `mvn` 追加 `-N`（非递归）参数，只解析父工程自身，避免 reactor 报错。
  - 若未预先检测到缺失但 Maven 返回码非 0 且 stderr 含 "Child module ... does not exist"，则自动重试一次 `-N` 模式。
  - 普通 jar 工程或所有子模块均存在时保持原有递归行为，不添加 `-N`。
- 新增 `tests/test_maven_resolver.py::TestMvnTreeMultiModule`（4 用例：缺失模块直接 -N、全部存在不 -N、运行时失败回退 -N、普通工程不 -N）。全量 **60 单测通过**（原 56）。已重建 `DTrack_offline.zip`（61 项）。
